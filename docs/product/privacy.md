# Приватность: аналитика и отчёты о сбоях

Решение по этапу 2. Приложением пользуются несовершеннолетние (ученики) и их родители, поэтому **сторонней продуктовой аналитики в приложении нет**: ни Firebase Analytics, ни Amplitude, ни рекламных SDK. Собираем только то, без чего нельзя чинить и развивать продукт, и только у себя.

## Что уходит и куда

| Что | Куда | Что внутри | Включено |
|---|---|---|---|
| События использования | `POST /api/analytics/events/` на наш бэкенд | имя события, время, платформа, версия приложения, роль и школа (их сервер берёт из сессии), 4 разрешённых свойства | всегда, для вошедшего пользователя |
| Отчёты о сбоях | наш бэкенд, `POST /api/analytics/crashes/` (таблица `crash_reports`) | тип ошибки, сообщение, стек, признак фатальности, платформа, версии приложения и ОС | всегда, в том числе без входа; пользователя в запросе нет |
| Пуш-токен | наш бэкенд, затем FCM | токен устройства | после согласия на уведомления (см. README) |

## События

`app_open`, `login`, `checkin_start`, `checkin_success`, `checkin_fail` (`reason`), `roll_call_done` (`seconds`, `absent`), `homework_created`, `push_open` (`type`), `excuse_sent`, `report_card_download`, `feedback_sent`. Другие имена приложение даже не ставит в очередь, а сервер отбрасывает.

Свойства: только ключи `reason`, `seconds`, `absent`, `type`; значения только числа, булевы и коды вида `[a-z0-9_.-]{1,40}` (свободный текст отбрасывается). Клиент вырезает остальное до отправки (`lib/core/analytics.dart`, `cleanProps`), сервер проверяет ещё раз.

## Чего нет

- **Идентификатора пользователя.** Ни user id, ни student id, ни имени, ни почты, ни токена устройства в событиях нет; сервер хранит событие без связи с учётной записью.
- Содержимого: текстов отзывов и заданий, оценок, имён, фотографий, координат.
- Рекламного идентификатора, IDFA/GAID, отпечатка устройства.
- Скриншотов и иерархии экранов в отчётах о сбоях.
- Сторонних сервисов для крэшей (Sentry и подобных): данные детей не покидают наш сервер.

## Отчёты о сбоях

- Ловим `FlutterError.onError` и `PlatformDispatcher.onError` (`lib/core/crash_reporting.dart`). Запрос без авторизации: работает и у вышедшего пользователя; сервер ограничивает 30 запросов в час с одного адреса.
- Тело: `{platform, app_version, os_version, crashes: [{error_type, message, stack, fatal}]}`. Ни user id, ни токена, ни устройства, ни хлебных крошек, ни заголовков.
- Чистка на телефоне до отправки (`scrubText`): e-mail, номера телефонов, JWT и `Bearer`-токены, query-строки в URL; сообщение ≤ 500 символов, стек ≤ 8000. Сервер чистит ещё раз.
- Очередь до 20 отчётов хранится в файле, переживает перезапуск, при переполнении старые выбрасываются. Одинаковая ошибка не ставится в очередь чаще раза в минуту. 4xx (кроме 404/429) выбрасывает пачку, сеть/5xx/429 — оставляет до следующего запуска.
- Только в отладочной сборке (`kDebugMode`): долгое нажатие на строку «О приложении» в профиле вызывает тестовый сбой. В релизе этого кода нет.

## Очередь событий

Событие сначала попадает в маленькую очередь (до 100, хранится в `prefs`), уходит пачками по ≤ 50 при паузе приложения, возврате и через 5 секунд после последнего события. Нет сети или сервер ответил 5xx — очередь ждёт; 404 (эндпоинт ещё не выкачен) — приложение молчит 30 минут; 400 — пачка выбрасывается. При выходе из аккаунта очередь стирается: события одного человека не должны уйти под другой сессией.

## Блокировка приложения

Face ID / отпечаток / код телефона (`local_auth`) — опция в профиле, по умолчанию выключена. Биометрия остаётся в системе: приложение получает только ответ «подтверждено / нет». Выход из аккаунта выключает блокировку.
